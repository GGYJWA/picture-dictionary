# 项目持久化与抗删除说明

> 回答用户的问题：后续会不断更新，如何保证产出不偏离要求？文件保存到云端，即使本地/后台文件被删，助手仍能按规范继续产出。

---

## 一、问题拆解

用户的担心有两个：
1. **产出偏离**：项目越做越大、会话越来越多，助手可能忘了早期的硬性要求（文风指纹、排版规格、自检流程等），写出不合格的东西。
2. **文件丢失**：本地或后台文件被删除后，助手无据可依，只能凭记忆"大约那样"，必然走样。

解法是建立 **Single Source of Truth（唯一权威源）＋ 多副本 ＋ 强制读取流程**。

---

- 位置：仓库 `GGYJWA/picture-dictionary` 的 `specs/` 目录，9 个文件

- 优点：公网可读、有版本历史、可追溯、不依赖本机

## 三、恢复流程（文件被删后）

1. 助手从记忆里看到规范源位置（GitHub 仓库 specs/）
2. 用 **GitHub Contents API** 读回文件：
   ```
   GET /repos/GGYJWA/picture-dictionary/contents/specs/<文件名>
   ```
   返回的 `content` 字段是 base64，解码即得原文。
   - ⚠️ **不要用 raw.githubusercontent.com**——本机代理下该域名超时（实测）
   - ⚠️ git push 在本环境因代理失败（502/超时），API 是唯一稳定通道
   - token 若失效，向用户索取新的（权限 Contents: read 即可）
3. 对照 ima 副本核验完整性
4. 恢复到本地工作区，**然后才继续产出**

## 四、防偏离的强制流程

### 开工前（新会话 / 新章节）
- [ ] 读完整规范（`白皮书_制作规范_约束文件.md`）
- [ ] 读对应章节的配图索引（了解已用图片和自检记录）
- [ ] 读文风指纹规则（三句式，避免自创）
- [ ] 核对后再动笔——**严禁凭记忆直接写**

### 交付前（每条/每章）
- [ ] 对照约束文件 9.5 节的 10 项自检清单逐条勾选
- [ ] 关键项：八段式齐全、指纹三句式轮换、配图逐张自检去水印、分章色正确、`detect_overflow.py` 输出「✅ 无溢出」、PDF 页数/图数对、网页 data.json 同步

### 规范变更时
- 先改本地权威源 → 同步 GitHub specs/ → 同步 ima 副本 → 更新记忆
- **三处全部同步后变更才生效**，避免各处规范打架
