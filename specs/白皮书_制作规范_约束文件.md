# 《把画面说给AI听》白皮书 · 制作规范（约束文件）

> 本文件是全书制作的**权威约束**，后续所有词条编写、配图、排版、导出必须严格遵守。
> 适用范围：全 7 章 112 条。前三章已按此规范完成，作为范例。
> 更新日期：2026-11-18

---

## 一、定位与读者

- 书名：**《把画面说给AI听》**，副标题「面向 AI 初学者的画面感词典」。
- 读者：所有 AI 初学者；高深用户不是目标读者。
- 核心定位：**画面感词典，不是提示词技巧书**。核心任务是"让人认出画面"，不是"教人写提示词"。
- 差异化：读者记住概念词 → 用 ima 现场出词，不必背英文。

## 二、文件写作要求（每条词条）

### 2.1 硬性结构（七段式，缺一不可）
1. `## 编号 中文术语名：一句有故事感的副标题`
2. **开场段**：一个画面感场景或吸引人的问题，娓娓道来（2–4 句）
3. **原理段**：讲人话解释术语，用比喻让它好懂（3–6 句），关键术语**加粗**用中文全称
4. `[配图：...]` 配图标注
5. **两版提示词**：中文版在前（国产工具直接粘），英文版在后（反引号，给 AI 看的）
6. **搭配建议段**：和谁搭、别和谁搭，口语化
7. **指纹句段**（版权暗门，见 2.4）
8. `*知识来源：《书名》*` 收尾

### 2.2 文风
- "有人感"：像老师讲课，娓娓道来、轻松、有适度幽默。
- 严禁"把知识点甩脸上"的七格式词条、干巴罗列。
- 比喻要贴切、口语要自然，可参考范例的"一个唱红脸一个唱白脸""俩人凑一块准打架"。

### 2.3 术语与英文
- **术语写全称，不用缩写**：写"四十五度"不写"45°"、写"三十五毫米"不写"35mm"。
- 正文以中文为主，**英文只出现在英文提示词反引号块**里。
- 中文提示词是描述性短语串（按国产工具习惯），不是英文的逐字直译。
- 中英两版内容一一对应。

### 2.4 版权暗门（文风指纹，必须严格执行）
- 每条词条的指纹句段，**必须**用以下三种固定句式之一开头，均匀轮换：
  - 「这里有个坑，作者当年亲自踩过：」
  - 「先替你把雷排了：」
  - 「这一条有个隐藏脾气，得提前说：」
- 三种句式在全书高频、成体系出现构成版权"表达特征"。**不得自创句式、不得漏用**。
- 严禁植入虚假信息（假词条/错参数）——本书提示词会被真的复制出图、检索调用，假信息会伤 core 资产。
- 详细规则见 `暗门设计_文风指纹规则.md`（内部文件，不随书发布、不进 ima）。

## 三、配图要求

### 3.1 分级策略
- 光影/色彩/氛围（1、5、7章）→ A/B 控制变量对比图
- 构图/风格（3、4章）→ 单图为主
- 纹理材质（6章）→ 单图
- 全书导读 → 1 组"用 vs 不用"钩子图

### 3.2 工艺铁律
1. 材质类 → 纯文生图（主体稳定）
2. 氛围/画质类 → 图生图锁基准（防换主体）
3. 风格类 → 纯文生图（风格本就重构整图）

### 3.3 逐张自检（每次生成必做）
每张图生成后用看图工具实际打开，逐项确认：
1. 主体是否正确（没换脸/换物/多肢体）
2. 目标词效果是否出来
3. 控制变量是否干净（A/B 除目标变量外一致）
4. 无 AI 瑕疵（畸形五官、扭曲文字、多余元素）
5. 风格是否符合词条
6. 标注"示意图·仅供参考"
- 变量生效但主体/场景被污染 → 图生图锁基准重做
- 未生效或严重瑕疵 → 调整 prompt 重生成
- 详见 `白皮书实测/配图自检规范.md`

### 3.4 去水印（必须）
- 出图工具会在右下角强制加"AI生成/WORKBUDDY"角标，参数无法关闭。
- 处理：`sips -c 890 1024 原图.png --out 成品.png`（裁掉底部 134px，1024×1024→1024×890）。
- 必须裁 134px（裁 55/100px 会残留文字）。成品存 `去水印/` 子目录。
- 环境：pip/npm 安装被沙箱拦截，用系统自带 sips。

## 四、排版视觉规范（陶阿狗君风格）

- 风格关键词：极简白底 + 单色巨字 + 纯黑粗框 + 杂志卡片排版 + 单一强调色贯穿。
- **按章节分色**：光影朱红 `#E8462F`、镜头宝蓝 `#2E5CE8`、构图金黄 `#C8890B`（后续章另定，保持每章一色）。
- 中文巨字（不用英文巨字），字号按短名字数自适应（屏幕版）；打印版全页统一固定字号。
- 正文白底黑字；提示词用浅色区分区块；重点处加色标注。
- 封面：大字报式巨字书名 + 正文微像素随机散布（大小/位置随机、不均匀、不遮字）。

## 五、PDF 导出规范（关键，必须遵守）

### 5.1 一条一词一条一页
- 每个词条**独占一页**，绝不允许跨页切割（破坏词条排版一体性）。
- 实现：`@media print` 里 `.entry{page-break-before:always; break-inside:avoid}`。

### 5.2 固定满页网格（版式规格全页一致）
- `@page{size:A4;margin:13mm}`，A4 可用高 271mm。
- `.entry{height:271mm; display:flex; flex-direction:column}`，四块分区：
  - 标题框：`flex:0 0 58mm`，巨字**统一 76px !important**（不随词条变）
  - 正文+图框：`flex:1 1 auto` 弹性吃剩余，字号固定，内容少则自然留白，框不变
  - 提示词框：`flex:0 0 62mm`，flex 纵向
  - 来源行：作为提示词框内最后一行，`margin-top:auto` 贴框底右下角（**必须在框内**）
- 配图 `height:100%; object-fit:cover` 填满图框，画面大小全页一致。
- 核心原则：**字号、画面大小、区块规格全页统一，字数差异只体现为框内留白**。

**⚠️ 必防的坑——Grid 正文框撑破遮挡（已踩过并修复）：**
- 正文框是 CSS Grid，子项默认 `min-height:auto`，文字一多就撑破格子、压到下面提示词框，造成正文与提示词重叠遮挡。
- 必须同时做到：`grid-template-rows:minmax(0,1fr)` + `.card .text{min-height:0;overflow:hidden}` + `.card{overflow:hidden}`。
- 字号/行距设为能容纳**最长词条**的固定值（当前正文 12.5px / line-height 1.68 / 段距 9px / 指纹句 11.5px）。曾经 13.5px/1.85 导致 14 条溢出（最多 59px）。

**导出前必跑溢出检测**：`python3 detect_overflow.py`（在 BASE 目录）。它模拟打印样式测量每个 `.text`/`.prompt` 的 scrollHeight-clientHeight，必须输出「✅ 无溢出」才能定稿。只要有一条溢出，就调小正文框字号/行距，不要靠截内容。

### 5.3 导出命令（Chrome headless）
```
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless \
  --disable-gpu --no-sandbox \
  --print-to-pdf="输出.pdf" --print-to-pdf-no-header --no-pdf-header-footer \
  "file://$(pwd)/输入.html"
```

### 5.4 图片内嵌（防丢图）
- HTML 用本机绝对路径会导致预览丢图。必须把图片转 JPEG（sips 质量 68）后 **base64 内嵌 data URI**，HTML 自包含。
- 43 张图压缩后 HTML 约 17MB，PDF 约 9.4MB。

### 5.5 导出后验收（必做）
1. 页数 = 词条数 + 章节页数 + 封面 + 尾页（前三章 47+3+1+1=52）
2. 用 PDF 工具提取图片，确认图片数与词条数匹配
3. 渲染若干页图，确认：内容铺满、版式一致、来源行在框内、无跨页溢出

## 六、ima 检索版

- 每词条一节，`##` 标题 = `【提示词】+ 术语名 + 中文俗称/白描/英文别名`（别名越多越好命中）。
- 含中文版 + 英文版两行提示词。
- **不加文风指纹、不加中文提示词长串**（避免稀释检索命中）。
- 命名：`把画面说给AI听_ima检索版_第X章.md`，导入 ima 库根目录。
- 检索验证：带术语/英文/提示词字样的查询应命中第 1。

## 七、可复用工具

- `build_ebook.py`：Markdown + 配图 → 陶阿狗风 HTML（含打印样式、base64 内嵌、微像素封面）。
- `build_ima_structure.py`：Markdown → ima 检索版。
- 后续章节：把章节文件路径加进脚本的 `chapters`/`files` 列表即可套用同一模板。

## 八、交付清单（每章）

## 九、规范持久化与抗删除机制（最高优先级）

> 背景：用户要求——后续会不断更新本书；即使本地/后台文件被删，助手仍须按原规范继续产出，不得偏离。

### 9.1 权威规范源（Single Source of Truth）
**本文件（`白皮书_制作规范_约束文件.md`）是全书的唯一权威规范源。** 一切词条写作、配图、排版、导出、网页同步，以本文件为准。任何与本文件冲突的做法，一律以本文件为准。

### 9.2 三份云端/持久副本（缺一不可）
1. **GitHub 仓库主副本**：`https://github.com/GGYJWA/picture-dictionary`，`specs/` 目录。存放本文件 + 全部配套规范文件 + 生成器脚本。公网可读、有版本历史、可追溯。
2. **ima 知识库副本**：知识库 `画面提示词`（`ima_kb_M6Ibw5sE`），上传本文件的规范摘要，作为第二副本。
3. **助手跨会话记忆**：助手的用户级/项目级记忆中记录规范源位置与恢复方法，确保新会话能找到前两份。

### 9.3 恢复流程（本地文件被删时）
若本地工作区文件丢失，助手必须：
1. 从 GitHub 仓库 `specs/` 目录拉取全部规范文件（用 API 或 git）；
2. 对照 ima 副本核验完整性；
3. 恢复后才可继续产出，**严禁凭记忆"大约是那样"自行发挥**。

### 9.4 每次开工前必做（防偏离）
- **新会话/新章节开工第一步**：读本文件 + 对应章节的配图索引 + 文风指纹规则（`暗门设计_文风指纹规则.md`，在 specs/ 中也有副本），核对后再动笔。
- 不得跳过此步直接凭印象写——这是"产出偏离要求"的头号原因。

### 9.5 交付自检清单（每条/每章交付前逐条勾选）
- [ ] 词条八段式齐全，文风指纹句三种固定句式轮换，无自创、无漏用（对照第二章 2.4）
- [ ] 术语中文全称，英文只在反引号块
- [ ] 配图逐张自检通过（对照 `配图自检规范.md` 六项），去水印裁 134px
- [ ] 配图索引已更新（文件名 + 自检结论）
- [ ] 生成器已纳入新章节（分章色 + 图片映射 + 英文副标 + chapters）
- [ ] `python3 detect_overflow.py` 输出「✅ 无溢出」
- [ ] PDF 页数 = 词条数 + 章页数 + 封面 + 结束词 + 尾页；图数 = 词条数；0 空页
- [ ] 渲染抽查：满页网格、分章色、来源行在框内、封面/结束词正常
- [ ] 网页 `data.json` 与配图同步更新，GitHub Pages 重建后验证
- [ ] 规范文件如有改动，已同步到 GitHub `specs/` + ima 副本

### 9.6 规范变更流程
规范本身若需修改：先改本地权威源 → 同步到 GitHub `specs/` → 同步 ima 副本 → 更新记忆。**三处全部同步后变更才生效**，避免各处规范不一致导致产出混乱。
